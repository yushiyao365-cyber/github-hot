# GitHub Radar · 个人技术雷达

本机运行的个人技术发现平台，以 Paimon、Agent Skills、大模型研究和 AI 工作流为四个内容模块。GitHub 仓库与公开文章共同提供候选，再调用用户配置的模型分析资料，给出有原文依据的判断。不会生成虚构热度，也不会安装 Skill 或执行采集的代码。

**模型未配置时只有规则候选，不是 AI 精选。** 模型接口已实现，不内置模型、账号、订阅或 API Key。测试中的模型输出来自隔离的测试服务，不能当成真实模型能力验证。

## 四模块工作台

左侧导航为今日精选、热点榜、精选历史、我的清单。设置在顶栏齿轮和“模块设置”；链接收录、手动同步与分析在页面内部。

「全部动态」已从主导航和页面路由移除，避免将原始采集队列当成阅读推荐。已收录数据、收藏、历史及后台自动采集与审核均保留；排查采集情况仍可使用今日精选内的「发现候选」。原只读 `GET /api/activity` 接口保留兼容，但不再作为面向用户的阅读入口。

| 模块 | 来源与选择方式 |
| --- | --- |
| Paimon 生态 | Apache Paimon 本体、直接集成项目，以及正式 Release 能力说明；公开落地文章可以手动收录。只提及名字不够入选。 |
| Skills | GitHub 检索及 `anthropics/skills`、`vercel-labs/agent-skills` 种子仓库；每仓库最多索引 1000 个 `SKILL.md`，每个文件有独立 ID、报告和收藏。初始预读最多 3 个文件，其余按审核队列逐个读取，不再只评价集合。正文最多 24000 字符，不执行指令或安装依赖。 |
| 大模型论文 / 白皮书 | 自动 arXiv 检索，另支持手动导入公开 HTML 技术报告或 PDF。PDF 使用本机 `pdftotext`，最多 2 MB、前 30 页、24000 字符，不 OCR、不解密、不声称读完全文。 |
| AI 工作流实践 | GitHub 中的 AI 工作流项目，以及 Simon Willison、Hugging Face、少数派订阅；跨研发、数据、文案、短视频、办公等场景，模型仍需验证具体任务、步骤、亮点和边界，不将模板称为生产验证。 |

- 首页每日总上限沿用原设置，另有四个独立模块上限；按模块轮流分配，有空位也不使用未分析或观察内容凑数。榜单上限独立配置。清单与发现候选按模块每页 24 条。
- Skill 榜可切换来源仓库实测增速、总 Star、近期新增 / 变更。独立 Skill 必须逐条通过实质步骤、适用工具与引用校验，不继承仓库推荐。初次导入是存量基线，不标成新发布；后续完整树快照发现新增路径或 blob SHA 变化才标注本机观测时间，不代表作者发布时间或能力提升。老仓库里的新 Skill 也可入选。增速来自有效本地采样，Star 是来源仓库指标，不是单个 Skill 的使用量；没有样本不伪造。
- 首页 Skills 交替考虑存量与近期变化的合格内容，同仓库最多 1 条；热点榜同仓库最多 2 条，防止大合集刷屏。存量 Skill 不套用论文/文章的 30 天过期窗，文件不可用则退出推荐；收藏和历史保留。旧仓库推荐在尚未索引独立文件时兼容展示，索引完成后首页与榜单由独立条目接替，旧仓库收藏不复制到每个子 Skill。
- 模块设置增加独立的候选审核吞吐：默认每轮最多 24 条、间隔 30 分钟（均可配置），项目与内容队列各自采用此上限；与首页展示数量无关，不再有 `dailyLimit × 2` 的每日尝试限制，也不会因精选已满停止审核。已有模型总预算仍有效，0 表示不限。失败条目退避 6 小时，限流和鉴权错误暂停当前批次，报告可复用时不重复调用。
- 独立 Skill 索引轮转每轮最多 8 个仓库，同一仓库至少间隔 6 小时；仓库树使用 6 小时缓存，blob 按不可变 SHA 缓存 7 天。树截断时不认定缺失文件已删除，也不把首次补全的文件误标为新增。只保证覆盖已发现的仓库及索引上限内文件，不保证全 GitHub 完整收录。Skill 自动分析跟随模型自动分析开关，沿用 GitHub Token、限流处理和共享模型配置。
- 页面采用中性白灰底色、深色标题与少量暖色排名强调。今日精选使用「四方向速览 + 按模块分组的单列阅读流」，速览直接复用当前入选条目，不额外查询或制造跨模块排名；后台任务提示收在正文末尾。
- 桌面主导航宽 184px，较窄桌面为 168px，手机仍为可收起抽屉。精选、热点、清单、历史导读与详情使用中文描述主标题，原始项目名/论文题名保留为次要信息。新报告生成可选 `titleZh`；旧报告直接复用已有中文概述，不为标题触发全量重审、不改写历史快照；缺少中文资料时显示待生成，不凭英文名称猜测用途。后端提示词改动需重启服务生效。
- 热点榜各模块使用「第一名大卡、第二三名侧卡、其余紧凑列表」，不足三条时自适应，不补位；手机改为纵向排列。四模块切换、收藏、原文和分析入口保持不变。上榜仓库显示近 30 天最多 31 个真实 Star 采样点，点击曲线可查看时间与数值明细；缺样本不补点。样本仅附加在热点榜响应中并按本地缓存复用，不增加首页负载或外网调用。
- 其余榜单称为“近期优选”，不把 GitHub Star、论文引用、文章阅读量混合成虚构分数。文章没有阅读量指标，按发布时间排列。
- 所有列表读取仅访问本地缓存，支持 ETag；采集与分析按现有调度运行。单源失败保留其他资料，公共阅读器保留域名、DNS、重定向、大小和超时限制。
- 启动时执行一次模块配置迁移：原偏好保存在 SQLite 的 `settingsBeforeRadarV1`，保留模型与密钥、每日预算、收藏、关注、备注及历史快照。旧清单中不能归类的项目单独保留入口；历史仅改变浏览分组，不重写快照。新版关注目标会使不兼容的旧报告等待重审。
- 发布前备份：`data/backups/radar-before-four-modules-20261009.sqlite`。凭据文件不在此数据库备份内，不修改现有凭据。

验证：`npm test`、`npm run build`、`npm run test:browser`。三个浏览器入口 `test:browser` / `test:hotlist` / `test:content` 统一运行四模块回归，使用隔离数据库与测试报告，不访问真实模型。后文保留底层采集、分析与兼容接口说明；旧版独立页面名称不再作为主导航。

## 启动

需要 Node.js 24 或更新版本（使用内置 SQLite）。

```bash
npm install
npm run build
npm start
```

浏览器打开 `http://127.0.0.1:4310`。开发时可运行 `npm run dev`，前端地址为 `http://127.0.0.1:5173`。

可通过环境变量调整服务端口和本地数据目录：

```bash
PORT=4310 RADAR_DATA_DIR=./data npm start
```

开发服务器代理默认指向 4310；修改开发后端端口时需同步调整 `vite.config.ts`。

## 第一次使用

1. 点击“同步数据”从 GitHub 获取真实数据。无 Token 每轮最多 4 条主题查询，四频道全开时首批交错覆盖两个高星查询与两个潜力查询，继续同步可完成其余查询；界面明确显示有限模式及采集不完整状态。
2. 在“偏好设置”中设置每日精选上限（默认 12）、高星门槛（默认 1,000）、潜力项目创建窗口（默认 365 天）、潜力名额占比（默认 50%），以及频道权重、关键词、Topics 和排除词。保存立即生效，重启后保留。
3. 在“我的清单”输入公开 GitHub 仓库地址或 `owner/repo`，也可以在项目卡片上关注更新。默认关注列表为空。
4. 推荐配置一个仅用于读取公开资料的 GitHub Token，不需要写权限。凭据为空时可继续浏览缓存和有限同步。
5. 在“分析模型与中文摘要”中填写 Chat Completions 或 Responses 接口的完整地址、实际可用的模型名称及密钥（免鉴权本机代理可留空），确认资料发送范围并启用。单纯填写 URL 不能证明服务可用；模型还需能返回约定的 JSON。
6. 启用“自动提炼首页亮点”并保存后，服务定时检查及发现同步完成时自动分析候选；首页只展示通过评审的项目，卡片直接展示用途、亮点和资料时间，不必逐个点击分析。全新安装默认不开启模型调用；已有用户的模型配置和开关保持不变。也保留批量、单项目手动分析。

### 绑定个人 GitHub Token

在 GitHub 个人 Settings → Developer settings → Personal access tokens → Fine-grained tokens 创建 Token（界面名称可能调整）。设置用途名称与有效期，仓库访问选择仅公开仓库，不添加写权限或私有仓库权限。本工具只读公开仓库，不需要 `repo` 全权限。

将生成的 Token 填入本机“偏好设置 → GitHub 连接 → GitHub Token”，保存即可，不要发到聊天或提交到代码仓库。设置页提供创建入口，并显示是否已保存及最近 GitHub 响应中的剩余额度。保存新 Token 会清除旧匿名请求的退避状态，下次定时检查可重新采集；新 Token 仍受 GitHub 实际配额约束。

### GPT-6 配置

使用官方服务时，接口填写 `https://api.openai.com/v1/chat/completions`，模型名称填写 `gpt-6-astra`，在本机设置页面输入有该模型访问权限的 OpenAI API Key，再确认资料发送范围、启用模型并保存。没有密钥时不要启用；填写模型名称不代表已经连通服务。

GPT-6 系列请求使用 `reasoning_effort: low` 和 `max_completion_tokens`，不发送 `temperature`。完成 token 上限在原文本预算上增加 4,096，为推理留出空间（不保证一定足够）；每日调用次数上限不等于费用上限。其他兼容模型保留原有参数。参数兼容性通过隔离测试验证，实际可用性仍需使用自己的凭据调用确认。

### 使用 CC Switch 已定义模型

如果 CC Switch 已管理上游凭据且开放免鉴权本机代理，Radar 的模型 API Key 可以留空，不需要复制 CC Switch 中的上游密钥。接口填写实际监听地址，例如 `http://127.0.0.1:15721/v1/responses`；模型名称须使用 CC Switch 当前配置中的实际模型 ID / 部署别名，而不是界面显示的配置名称。此地址是本机代理，并不代表模型在本机运行，公开项目资料仍会由代理发送到其上游服务。

在“偏好设置 → 分析模型与中文摘要 → CC Switch 模型（全部应用）”下拉框中，按 Claude Code、Codex、OpenClaw、Gemini 等应用分组列出所有配置，不再过滤为 Codex 或当前供应商。后端只读 `~/.cc-switch/cc-switch.db`，读取配置模型、模型目录和 Claude 环境变量中的真实模型 ID；Claude 的 `*_MODEL_NAME` 显示名称不作为模型 ID，配置别名被 `ANTHROPIC_MODEL` 覆盖时采用实际 ID，相同 ID 去重。只有登录卡、未配置模型或缺少 API 凭据的条目仍显示，但附不可选原因；不猜测账号可以访问的模型。

新选择的模型使用独立路由：平台直接调用所选配置的上游，不要求开启 CC Switch 代理、切换当前卡或关闭其故障转移，不修改 CC Switch 全局设置。支持 Responses、Chat Completions、Anthropic Messages、Gemini generateContent 四种协议；不支持的协议会注明原因。列表读取成功只证明配置完整，不保证上游在线、账号有权限或模型仍可用。

选择后自动填入真实上游地址及模型 ID，清除 Radar 旧模型 Key。凭据每次由后端从所选配置即时读取，仅发送给该配置的上游；不返回浏览器、不复制保存到 Radar 的数据库或凭据文件，也不读取或复用官方登录会话、OAuth Token。绑定包含应用类型，避免 Claude 与 Codex 的同名配置冲突；配置删除或上游地址等关键项改变时停止调用并提示刷新。密钥同类型轮换会在下一次调用使用新值。

保留“手动填写接口和模型”选项；手动修改地址或模型名称会解除绑定。CC Switch 未安装、数据库版本不兼容或读取失败时，手动配置仍可用。

原有 Codex 本机代理绑定继续兼容，不自动改动现有模型。该旧模式仍要求代理运行且当前配置不变；在全应用下拉框中重新选择后，才切换为独立上游调用。手动接口通过路径识别协议；Responses 设置低推理强度和 `store: false`，各协议仅采用完整文本响应，截断、工具调用或拦截不会作为成功报告。`store: false` 不保证代理或上游不保留日志。

## 双池与模型分析

### 专题精选试用版

在偏好设置的“我的关注专题”中点击“填入三个起始专题”并保存，可切换到专题模式。起始配置为 Paimon 及其周边、训练数据工程落地、研发工作提效；它们只是可编辑的初始配置，不是采集代码写死的订阅。支持新增、修改、暂停、删除专题，最多 10 个。

- 每个专题配置名称、关注目标、检索条件、排除要求和权重。每行检索条件是一种备选；`dataset + deduplication` 表示两部分必须同时出现。排除要求由模型结合上下文审核，不是简单关键词封禁。
- 专题模式替代四个泛频道的搜索和双池配额。每个启用专题每周期最多 3 条查询，覆盖名称、描述与 README，分别找相关工具、新建项目和近期活跃项目，每条最多 30 个结果；每 6 小时轮换检索条件。高星、新建和增长作为辅助信号，不淘汰直接相关的老低星工具。
- 起始 Paimon 专题使用 Apache Paimon、Paimon + Flink / CDC / lakehouse 等领域组合，减少同名游戏项目干扰。审核顺序结合元数据命中、对数 Star 关注度、有限的新建与增长加分；新建的小演示不再仅靠年龄压过相关成熟项目。最终是否入选仍由证据审核决定。
- GitHub 检索命中只表示待评审，不能证明相关。模型必须给出与专题的直接关系、能减少的具体工作、试用方式及前提；这三项都要引用实质 README 或发布说明中的原文。仅沾边、不相关、缺少使用证据、旧版报告或低置信度报告不进专题首页，即使 Star 很高也不补位。
- 首页按专题权重分配总名额，同一仓库只出现一次，同专题内相同任务标签最多显示一个。任务标签由模型生成，因此这不是完整的语义去重，也不保证所有同类工具都会被识别。
- 首页与项目发现可按专题切换；项目发现默认只展示专题候选，勾选“同时显示专题以外的历史缓存”可查看旧泛领域数据。收藏与关注不受此过滤影响，不删除旧项目。
- 项目发现是候选库，包括待审核、观察、不推荐与已经入选的项目；精选是同一批数据中通过直接相关、工作价值和试用证据审核的子集，再按未读状态、专题配额和同任务去重收敛。两页共享收藏、关注、已读与分析结果，不需要重复分析。
- 列表卡片只显示两行用途、两行工作亮点和基础指标；“试用方式与证据”打开已有报告详情，保留关联理由、使用前提、更新依据和原文，不触发重新分析。使用说明不代表已经亲测好用，不凭创建时间或星数编造最新变化。
- 精选页不展示宣传横幅、完整专题目标或关注版本预览；后台模型、配额、错误与手动操作收进默认折叠的状态栏。选择一个 Tab 只显示该专题，不保留其他专题的空区块。侧栏“我的专题”是相同精选视图的快捷入口，和 Tab 联动；关闭专题模式时侧栏恢复“技术分类”，用于浏览候选，并非另一套精选规则。
- 修改目标、检索条件或排除要求后旧报告失效，并安排新一轮发现；仅改首页数量或专题权重可复用报告。专题目标和排除要求会发送给已配置模型，请不要填写个人秘密。个人备注、GitHub Token 仍不会发送给模型。
- 全新或旧版配置不被强制切换；关闭专题模式可以恢复原来的双池方式。保存不会改动模型、调用预算、收藏、关注或历史数据。

以下双池说明适用于关闭专题模式时；模型证据校验与调用预算在两种模式下均生效。

- **高星池**：达到配置门槛且匹配兴趣方向的项目。发现时按 Star 查询近期活跃项目，不要求仓库刚创建，也不因首次发现超过 7 天就淘汰。
- **潜力候选池**：低于高星门槛、在候选创建窗口内（默认 365 天），或已达到实测增长门槛的相关项目。自动精选进一步收紧到“新建项目或快速增长项目”，不是任意正增长都入选。
- **新建与快速增长**：新建窗口默认 30 天，依据真实创建时间；快速增长默认区间日均新增至少 10 Star。两个参数均可配置，新建搜索不设 Star 上限，不会漏掉因为已经超过高星门槛而被旧低星搜索排除的新仓库。
- **自动精选**：只展示模型结论为 recommend、置信度不为 low、资料未过期且符合主题与上述门槛的未读项目。卡片显示用途概述、最多两条有原文摘录支持的亮点、适用场景（如有）、来源采集时间。未评审、观察和资料不足的项目仍可在项目发现中查看，不用它们填满首页。
- 两池名额合计不超过每日上限；按配置占比分池，各池内部按频道权重分配，缺额可跨池补位。已读、忽略、归档和 Fork 不进首页；“初始推荐”不再另占一个固定数量区块。
- 模型报告包含：用途、为什么值得看、能力与技术特点、适用场景、风险、未知项、结论及置信度。置信度为模型自评，不是经过校准的成功概率。
- 结论分为“值得关注 / 继续观察 / 暂不推荐”。同一频道内优先已分析的正向结论，未分析项目明确标为规则候选；最新有效报告为“暂不推荐”的项目不进首页，但历史资料仍保留。
- 分析前按需获取 README 和最多 5 条近期 Release，报告使用最多 2 条正式版本说明；读取有限资料，不克隆、不执行代码，不自动调查外部竞品。
- 每个判断必须引用已提供的资料 ID 和连续原文摘录。不存在的来源或摘录导致报告被拒绝；这只能校验引用真实存在，不能保证模型推论正确。
- 只有元数据而没有足够正文时，系统把正向推荐降为“继续观察 / 低置信度”。没有增长样本时明确写“未知”，不会推算或伪造。
- 单批分析数量跟随可配置的每日精选上限，不再写死为 12 个。分析与摘要共享每日调用上限，设置为 `0` 表示不限制每日调用次数，正整数表示有限预算（新安装默认 12）；失败请求也计入用量。有效缓存不重复分析，可以多次启动完成剩余候选。不限次数不代表免费，也不会绕过模型服务自身的额度或限流。
- 内容未变时复用报告；公开资料、兴趣筛选、池门槛或模型变更后，旧报告标记过期并停止用旧结论参与 AI 排序。调整显示数量或个人备注不会使报告过期。
- 模型未启用、接口错误、输出格式或证据校验失败时，都不生成假报告；保留原文和之前的报告，并显示待分析、失败或过期状态。

## 数据与运行方式

- 页面刷新只读取本地缓存，不触发 GitHub 同步或模型分析。列表不携带完整分析来源正文，打开项目详情时再读；版本列表只传输当前关注项目的记录，未关注的历史版本仍保存在数据库中，仍可作为分析证据。
- 证据按仓库索引读取，不对每个项目重复扫描全库版本。列表响应短时缓存、数据库写入自动失效，并使用 ETag 在内容未变时返回 304；时间相关筛选最多 15 秒重新校验缓存。浏览器串行轮询，空闲 15 秒、任务进行中 4 秒，后台隐藏页面暂停轮询，返回前台立即检查。写操作完成后保证重新读取，不被更早的在途请求覆盖。

- 默认数据库：`data/radar.sqlite`；用户状态、版本记录、设置、摘要、分析报告和增长快照都保存在其中。旧版数据库新增表并补齐配置默认值，不清空原有数据。
- 凭据：`data/secrets.json`，文件权限为 `0600`、数据目录权限为 `0700`。这是受文件权限保护的明文存储，不是系统钥匙串或加密保险箱。不要分享该目录。
- `data/`、测试产物、依赖目录已加入 `.gitignore`。
- 服务运行且配置 Token 时，每 6 小时检查发现任务；关注项目每 6 小时检查版本。无 Token 不做自动广泛搜索，但开启自动分析后仍能处理缓存资料。启动后及每分钟检查任务是否到期，任务互斥，不会并发刷接口。
- 自动分析采用独立审核批量和间隔（默认每轮 24 条、30 分钟），不再与首页上限绑定，也不因精选已满提前结束。有效报告复用、失败条目退避 6 小时；每日模型预算仍可为 0（不限），手动单条分析仍可继续。
- 只对分析短名单补齐 README / 发布资料。元数据与版本证据通常 24 小时内复用，README 最长 7 天或仓库 push 变化时刷新；支持 ETag / Last-Modified 条件请求，HTTP 缓存按 Token 隔离。限流时尊重恢复时间，有实质缓存的继续分析并标注资料可能滞后，无缓存的进入等待，不生成假亮点，也不阻塞其他项目。
- 电脑休眠或服务退出后不采集；启动后检查是否需要补同步。无需额外守护进程。
- 初次采集仓库仍记录真实创建时间与首次发现时间，直接按双池规则进入候选；旧版本保留历史标记，不冒充当天新发布。
- 已读项目不反复进入首页，未读的成熟高星项目不因首次发现较早而被移除。重要版本变化通过关注更新呈现。
- 模型只接收公开仓库资料、当前频道关键词及公开指标快照，不发送个人备注、收藏列表、GitHub Token 或其他本地文件。模型地址改到不同服务域名时，若没有重新填写 Key，会清除旧 Key，避免跨服务误发。

## 技术热点榜

- 默认总览同时展示「开源项目 / 大模型论文 / AI 工具实践」，各提供前三条导读，切换类型查看完整榜单。项目仍按真实采样区间日均增星排序；论文和实践暂没有引用/阅读/讨论增速来源，明确标注为「近期优选 · 非热度排行」，不与 Star 混算分数。
- 论文与实践仅采用当前阅读目标内、窗口内、有效且直接相关的推荐报告，按原文发布时间降序各最多 10 篇；未知发布时间置后并按首次收录时间排序，同时间按 ID 稳定排序。独立于首页名额，已读仍可上榜，忽略/过期/观察/未分析的内容不上榜。支持原文证据详情、收藏和忽略。禁用类型时保留入口并解释原因，不塞入待审核文章凑数。
- 新增 `/api/content/hotlist`，仅查本地缓存，ETag 与 15 秒缓存随数据库修改失效；查看榜单不调用外部服务，也不写入精选日报。

- 左侧「热点榜」单独观察增长：前三名突出展示，第四到第十名紧凑排列，可按专题/频道切换、收藏、打开项目分析或点击趋势查看采样明细。
- 与精选的区别：从本机全部合格相关项目中，按实际采样区间的日均净增 Star 降序取前 10，不受首页数量、已读状态和同任务去重影响；忽略、归档和 fork 不上榜。同速依次按相关性评分、总 Star、仓库 ID 排序。
- 专题模式只接收当前有效、直接相关、有关系/收益/试用依据的中高置信推荐；非专题模式启用模型时也要求有效推荐。只有非专题且关闭模型时才展示明确标注的规则候选。不为填满榜单放宽审核。
- 两个样本须相隔 1–14 天，最新样本不超过 3 天且净增为正。大数字为采样区间的整数净增，小字显示间隔和排序用的日均值，不是讨论热度、24/48 小时榜或精确今日新增。
- 曲线只连接近 30 天的本机真实 Star 采样点，横轴用实际时间，纵轴按各项目独立缩放；不补点、不插值成观测数据、不计算虚构趋势百分比。点击可查看原始时间与 Star。
- 榜单按需读取本地接口，15 秒缓存并支持 ETag，数据库变更使缓存失效；页面隐藏暂停轮询。不增加 GitHub、模型调用，不把曲线塞进首页轮询数据。

## 每日精选历史

### 精选首页

- 首页采用「当前精选速览 + 按日期分组的时间线」：顶部最多展示当前过滤结果的前 5 个项目，点击可定位卡片；后端入选范围、数量上限和推荐顺序不变。专题和搜索同时作用于速览与正文。
- 增长直接显示采样区间净变化，例如「5.5 天 +1 ★」，Star 增减量保持整数；悬浮说明展示两个采样时间、起止 Star 和区间日均值。小数天数表示实际间隔的近似值，不是今日涨幅。精选榜单、精选卡片与发现卡片使用同一展示口径；筛选、排序仍按原有实测日均增速，不生成热度分或模型评分。未知增长标为「待采样」，过期数据标为「旧快照 · 待更新」。时间线使用有效报告的分析时间，未分析项目使用采集时间，不把旧项目包装成当天发布。
- 单列卡片直接展示项目概述、亮点和推荐依据，保留快照证据详情、收藏、关注、已读与忽略。后台采集/审核操作折叠放在列表末尾；详细版本动态仍在「版本动态」页面。

### 往期日报

- 日报标题更新为「精品日报」，常驻「全部 / 开源项目 / 大模型论文 / AI 工具实践」切换及本期数量，未入选类型显示原因，不隐藏入口。顶部三类导读与右侧看点优先各取一条，不让项目挤掉论文和实践；后台分析完成后会更新日期目录与当期内容，但历史详情仍使用冻结快照。

- 首页点击「往期精选」，或侧栏进入「精选历史」，以日报形式回看当天入选项目：左侧按月列出往期日期与首条摘要，正文展示日期、项目/专题/分析数量及精简项目条目，右侧提供看点与专题目录。支持归档日历、专题筛选和前后期切换；手机端使用日期选择器，不挤入多列布局。
- 日报按历史专题编排，编号保留存档顺序，不是额外计算的热度排名；首条放大只是阅读层级。不生成新闻配图、虚构看点或额外模型总结。
- 按本机时区归档，每个项目每天只保存首次入选快照：仓库指标、所属专题、模型判断、亮点、README 与引用证据。后来已读、忽略、修改专题或重新分析，不会改写快照。历史详情只读，不调用 GitHub 或模型。
- 首页上限仍由偏好配置；历史是当天入选项目的去重合集，日内已读后的补位可能使归档总数超过首页同时显示的上限。未读项目若次日继续入选，会在次日再次留档，并非「当日新建仓库榜」。
- 从功能启用起记录，不用当前数据反推过去榜单；无精选或服务未运行的日期不生成记录。启动后、每分钟、分析结果完成后及读取首页时保存实际入选结果，不要求浏览器一直打开。
- 快照保存在本机 SQLite 的 `featured_history` 表，不包含个人备注、收藏/关注状态或模型连接配置。历史按日期按需读取，首页轮询不携带整份历史，列表不携带 README 和证据全文。

## 大模型论文与 AI 工具实践

- 论文按「阅读价值」而非「是否已验证可落地」审核：直接契合目标、研究问题与方法/贡献明确，并有摘要依据支撑阅读启发即可推荐阅读；只有摘要、未同行评审或缺少完整实验设置不单独构成降级理由。缺失信息继续标注，作者实验数字不当作独立验证。贡献不清、相关性不足或泛宣传仍保留观察/跳过，原文引用校验不放宽。此标准更新只使旧论文报告待重审，不改写既有判断或历史快照，不使项目/实践缓存失效。

- 侧栏新增「大模型论文」「AI 工具实践」。论文关注推理、多模态、训练/后训练、Agent、RAG、评测与效率；实践关注不同项目里实际怎样使用 AI：任务、工具、步骤、人机分工、结果检查、效果和踩坑。两类内容的目标、发现词、是否启用和首页名额分别配置，不使用 GitHub 专题替代这些偏好。
- 论文从 arXiv API 按标题/摘要、计算机相关分类和时间窗口检索，每轮最多 30 条；记录作者、发布时间、版本与原文地址，按不含版本号的 arXiv ID 去重。**第一版只分析摘要，不下载 PDF，也不声称读过全文、核实实验或确认会议录用。**
- 实践从可配置的公网 HTTPS RSS/Atom 订阅获取，默认提供 Simon Willison 与 Hugging Face Blog；每个源每轮最多读取 60 条。优先审核有具体使用/构建/步骤等线索的内容，再按时间排序。没有摘要的 RSS 也能按标题初筛，只有候选才补抓公开正文。支持手动添加 arXiv 链接或公开实践文章；不是全网搜索，也不能保证覆盖所有行业用例。
- 开启后默认每 6 小时采集一次，每 30 分钟检查待分析候选；四模块模式采用模块设置的审核批量（默认 24），按模块轮转，Skill 内再按仓库轮转。旧版兼容模式沿用内容批量设置（默认 6）。**每轮数量不是每日调用上限**，项目、Skill、论文、实践和摘要共用已有模型与每日预算，预算 0 仍表示不限。任务串行互斥，浏览页面不触发外部请求；失败来源独立报告，原始资料保留。
- 模型提炼中文亮点，并给出推荐/观察/跳过、直接相关性和原文引用。引用必须确实存在于提供的文本；实践必须有正文摘录、工具和至少两个不同步骤依据，论文需有贡献依据，且直接相关、非低可信才能入选。新鲜度窗口默认 30 天，可配置；资料或阅读目标/模型变化会使旧报告过期。名额与预算变化不会使已分析文章重复调用模型。
- 首页增加「全部 / 项目 / 论文 / 实践」筛选，三类内容共享每日精选总上限，按类型轮流分配；论文、实践默认各最多 3 篇，不足不凑数、剩余名额可由项目补充。技术热点榜分类型展示，项目用实测 Star 增长，论文/实践用近期优选，不混合虚构热度。项目专题和项目搜索只作用于项目。
- 每张文章卡直接展示介绍、贡献/做法和启发；详情提供原文依据、实际读取的文本和不确定性。支持收藏、已读、忽略；「我的清单」包含收藏文章。「精选历史」合并三类内容，保存首次入选的不可变快照，支持只有论文/实践的日期，不用新报告覆盖旧判断。
- 新增 `content_items`、`content_history` 两张 SQLite 表，不改写原有仓库、Token、CC Switch 绑定和收藏。全新配置默认关闭新内容模块，启用及数据发送范围在偏好设置中明确展示。开启自动分析会将公开标题、URL、摘要/摘录及阅读目标发送给现有模型，不发送用户阅读状态、个人备注、GitHub Token 或本地文件。
- 来源读取只允许无凭据公网 HTTPS 域名，每次 DNS 解析拒绝非公网 IPv4，并将连接固定到已校验地址；每次重定向重新校验（最多 3 跳），读取超时且限 2 MB。不访问本机/内网、执行脚本、解析外部 XML 实体、绕过登录/付费或下载二进制。当前不支持仅 IPv6 的来源；XML 为受限 RSS/Atom 解析，正文是尽力提取的纯文本摘录，不保证还原所有网站排版。遇到复杂格式或访问限制会显示失败，而不是生成假内容。

## 明确边界

- 搜索是按主题和窗口抽样：每个启用频道 3 条查询（近期活跃高星、新建项目、较宽创建窗口内的低星候选），每条最多 30 个候选。每日轮换关键词/Topics，没有管理或索引全部 GitHub 项目，也不能保证发现所有潜力项目。
- 第一版主要使用 GitHub Releases，不自动解析 Tag、官网版本说明、RFC 或 PR。没有 Releases 的仓库可能没有版本动态。
- 版本每轮每仓库最多读取 3 页，每页 30 条；未读完时保存游标，下轮继续。完成后的增量检查保留 7 天重叠窗口。
- 增长显示两个实际采样点之间的 Star 净变化与区间日均增量，不是精确的过去 24 小时涨幅。选取 30 天内距离最新样本最近、但至少相隔 24 小时的基线；保留负变化。用于快速增长判断的间隔不超过 14 天，最新样本不超过 3 天；其余标为旧快照。新安装时增长未知，需要连续采样积累，不能即时还原全 GitHub 历史日榜。
- 候选同步后限量回访至少 24 小时未采样的项目（有 Token 最多为首页上限的三倍且不超过 60 个，无 Token 最多 3 个），优先相关候选和关注项目；模型分析前也会刷新较旧元数据。采样不保证等间隔，不是全量趋势监控。项目发现支持按实测日均增星排序，未知增长排在已有数据之后。
- 模型协议需兼容 Chat Completions、支持低推理强度的 Responses、Anthropic Messages 或 Gemini generateContent 文本响应；分析需输出可解析的 JSON。不保证所有厂商或本机模型都兼容。
- 这是受控的“采集证据 → 模型分析”流程，不是可自由浏览、运行命令的自主 Agent。创新性、性能、成熟度和未来潜力的判断仍需结合原始资料核实。
- 应用不会下载、构建或运行被推荐仓库的代码；README 和版本说明均作为不可信文本展示。
- 仅设计用于单人本机使用，没有公网部署所需的账户认证体系。
